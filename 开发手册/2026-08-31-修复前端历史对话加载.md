# 修复前端历史对话加载

- 日期：2026-08-31
- 状态：已完成并验证

## 开发目标

前端页面初始化时未加载历史对话。后端 `GET /chat/{conversation_id}/history` 路由早已实现，但前端初始化只调用 `loadConfig()` 和 `loadSidebar()`，从未调用 history API，导致刷新页面后历史对话消失。

## 开发过程

1. **诊断**：确认后端 history 路由存在（`app/server.py`，调用 `_checkpointer.load(thread_id)` 返回 `{"messages": [...]}`），前端 `index.html` 初始化处（`loadConfig(); loadSidebar();`）缺少历史加载调用。
2. **实现**：在 `app/static/index.html` 添加 `loadHistory()` 函数，并在初始化时调用。
3. **验证**：浏览器刷新页面，45 条历史消息全部加载（18 user / 16 assistant / 11 tool_result），且新对话能正常继续，助手能记住历史上下文。

## 新增/修改代码

### `app/static/index.html`

新增 `loadHistory()` 函数（放在 `loadSidebar` 之后）：

```js
// ---------- 历史加载 ----------
async function loadHistory() {
  try {
    const data = await (await fetch(`/chat/${conversationId}/history`)).json();
    const box = $("#messages");
    box.innerHTML = "";
    data.messages.forEach(m => {
      addMsg(m.role, m.content);
    });
  } catch (e) {
    console.error("load history failed", e);
  }
}
```

初始化处新增调用：

```js
// ---------- 初始化 ----------
loadConfig();
loadSidebar();
loadHistory();   // ← 新增
$("#input").focus();
```

## 验证方式

1. 浏览器打开 `http://127.0.0.1:8000/`，刷新页面。
2. 确认历史对话（用户消息 + 助手回复 + 工具调用结果）全部显示。
3. 发送新消息，确认助手能引用历史上下文（说明历史已加载进模型上下文）。

## 说明

- 历史中的工具调用消息（role 为 tool）由后端 `_message_to_text` 转成纯文本，前端 `addMsg` 对非 tool role 直接 `textContent` 渲染，因此工具结果显示为普通文本气泡（无 🔧 标签）。这是可接受的 MVP 行为。
- 前端是静态文件，修改 `index.html` 后刷新页面即生效，无需重启服务器。
