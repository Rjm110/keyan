# HITL 挂起修复 + SSE 序列化修复 开发手册（2026-09-01）

> 开发内容：修复科研助手 HITL（Human-in-the-loop）流程的两个 bug：
> 1. **SSE 流挂起**：agent 触发 HITL 确认后，原始 `prompt()` 任务永不结束，导致 SSE 流挂起、前端报 `ERR_INCOMPLETE_CHUNKED_ENCODING`。
> 2. **`ask_user` 序列化崩溃**：`AskRequest.questions` 中的 pydantic `Question` 对象无法被 `json.dumps` 序列化，导致 SSE 流抛 `TypeError` 中断。
>
> 开发时间：2026-09-01

---

## 一、问题背景

科研助手使用 cubepi 框架的 HITL 机制：当 agent 调用修改类工具（`write_file` / `replace_in_file`）或 `ask_user` 时，会挂起等待用户确认。

cubepi 的 HITL 是**两阶段协议**：

```
阶段 1：prompt() → 检测到 pending → 必须调用 agent.detach() → 原始任务正常结束（发出 AgentSuspendedEvent）
阶段 2：respond() → 在新的 agent 实例上恢复执行（从 load_pending 恢复 run_id）
```

**根因**：`ChatService.post_message` 缺少阶段 1 的 `agent.detach()` 调用。pending 出现后，channel future 永远不被 resolve，原始 `prompt()` 任务挂起，SSE 流永不关闭。

## 二、修复方案

### 2.1 `app/services/chat_service.py` — HITL detach 监视器

在 `post_message` 中新增 `_watch_hitl()` 协程：轮询 `load_pending(thread_id)`，检测到 pending 后调用 `agent.detach()`，让原始任务正常结束。

```python
async def post_message(self, user_id, project_id, conversation_id, text):
    thread_id = await self._resolve_thread_id(user_id, project_id, conversation_id)
    run_id = uuid.uuid4().hex
    await self._conversation_service.ensure_title(thread_id, text)
    agent = self._build_agent(thread_id, project_id, run_id)
    queue: asyncio.Queue = asyncio.Queue()
    agent.subscribe(lambda event, signal=None: queue.put_nowait(event))
    task = asyncio.create_task(agent.prompt(text, run_id=run_id))

    async def _watch_hitl() -> None:
        load_pending = getattr(self._checkpointer, "load_pending", None)
        if load_pending is None:
            return
        try:
            while not task.done():
                if await load_pending(thread_id) is not None:
                    await agent.detach()
                    return
                await asyncio.sleep(0.05)
        except asyncio.CancelledError:
            pass

    watcher = asyncio.create_task(_watch_hitl())
    task.add_done_callback(lambda _t: watcher.cancel())
    return queue, task
```

**设计要点**：
- **轮询而非事件订阅**：避免与 SSE queue 消费竞争事件。
- **`task.add_done_callback` 取消 watcher**：任务正常结束后 watcher 自动退出，无泄漏。
- **`getattr` 防御**：兼容无 `load_pending` 的 checkpointer 实现。

### 2.2 `app/api/chat.py` — `Question` 序列化修复

`HitlRequestEvent` 的 `questions` 字段是 `list[Question]`（pydantic 模型），`json.dumps` 直接序列化会抛 `TypeError: Object of type Question is not JSON serializable`。

新增 `_jsonable()` 辅助函数递归转换：

```python
def _jsonable(value: object) -> object:
    """把 pydantic 模型/列表递归转换为 JSON 可序列化对象。"""
    if isinstance(value, BaseModel):
        return value.model_dump()
    if isinstance(value, list):
        return [_jsonable(item) for item in value]
    if isinstance(value, dict):
        return {key: _jsonable(item) for key, item in value.items()}
    return value
```

并在 `HitlRequestEvent` 分支中把 `questions` 字段包一层 `_jsonable()`。

## 四、经验总结

1. **cubepi HITL 是两阶段协议**：`prompt()` 检测到 pending 后**必须**调用 `agent.detach()`，否则原始任务永不结束。`run_id` 必须贯穿两阶段（`post_message` 绑定到 channel，`respond` 从 `load_pending` 恢复）。
2. **SSE 流关闭依赖任务结束**：`event_generator` 的 `finally: await task` 意味着任务挂起 = SSE 挂起。任何 HITL 挂起都会表现为前端 `ERR_INCOMPLETE_CHUNKED_ENCODING`。
3. **pydantic 模型不能直接 `json.dumps`**：跨层传递结构化数据时，序列化边界（API 层）需要递归转换。
