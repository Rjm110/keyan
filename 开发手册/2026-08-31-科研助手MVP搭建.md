# 科研助手 MVP 开发手册（2026-08-31）

> 开发内容：基于 cubepi 0.13.5 搭建科研助手最小 MVP——在 baseline 代码基础上，根据上传的论文和用户需求（对话框输入），修改 baseline 代码。
>
> 开发时间：2026-08-31

---

## 一、开发目标

实现一个 Web 版科研助手 MVP，核心功能：

1. **论文上传/读取**：用户把论文 PDF 放入 `workspace/papers/`，agent 可读取解析。
2. **Baseline 代码修改**：agent 读取 `workspace/baseline/` 下的代码，按用户需求修改。
3. **对话框交互**：用户在 Web 界面输入需求，agent 按"读论文 → 分析 baseline → 提方案 → 改代码 → 总结"流程执行。
4. **HITL 人工确认**：所有修改类工具调用前，弹窗让用户确认（approve/deny/edit）。
5. **多 provider 可配置**：支持 deepseek/qwen/kimi/glm/anthropic/openai。

### 2.2 本会话工作

1. **测试编写与调试**（核心工作）：
   - 编写 `test_fs_tools.py`（7 个测试）、`test_paper_tools.py`（3 个测试）、`test_agent_flow.py`（4 个测试）。
   - 发现并修复 **HITL details_fn bug**：`ctx.tool_name` → `ctx.tool_call.name`（`BeforeToolCallContext` 没有 `tool_name` 属性，只有 `tool_call`）。
   - 发现并修复 **run_id 绑定机制**：cubepi 0.13.5 的 `CheckpointedChannel` 必须绑定 `run_id`，`prompt(run_id=...)` 必须传相同值，否则 `_validate_hitl_bindings` 报 "generate-mode rejected" 或 "does not match"。
2. **mypy 修复**（111 个错误 → 0）：
   - `SQLiteCheckpointer` 是 PEP 562 惰性导入 → 改为 `from cubepi.checkpointer.sqlite import SQLiteCheckpointer` 直接导入。
   - `AgentEvent` 是 pydantic 联合类型 → 用 `isinstance()` 收窄（字符串比较 `event.type` 无法收窄）。
   - `agent.channel` 类型是 `HitlChannel` Protocol（无 `answer` 方法）→ 测试中 cast 为 `CheckpointedChannel`。
   - `ApproveAnswer.decision` 需要 `Literal["approve", "deny", "edit"]` 类型。
   - `post_message` 返回类型改为 `EventSourceResponse`。
   - 消息历史用 `msg.role` 而非 `msg.type`。
3. **ruff 修复**：未使用导入/变量清理，13 个文件格式化。
4. **手动验证**：uvicorn 启动、静态页面渲染、各路由 200、错误处理返回可读 JSON。

#### `app/agent_factory.py` — Agent 装配（HITL 核心）

```python
def build_agent(
    model: BoundModel,
    config: AppConfig,
    checkpointer: SQLiteCheckpointer,
    thread_id: str,
    run_id: str | None = None,
) -> Agent:
    channel = CheckpointedChannel(
        checkpointer=checkpointer, thread_id=thread_id, run_id=run_id
    )
    agent: Agent = Agent(
        model=model,
        system_prompt=build_system_prompt(config),
        tools=[*fs_tools, *paper_tools, ask_user_tool(channel)],
        middleware=[
            ConfirmToolCallMiddleware(
                channel,
                require_confirm=REQUIRE_CONFIRM,
                details_fn=lambda ctx: {
                    "tool": ctx.tool_call.name,   # 注意：不是 ctx.tool_name！
                    "args": ctx.args.model_dump() if hasattr(ctx.args, "model_dump") else str(ctx.args),
                },
            ),
        ],
        checkpointer=checkpointer,
        thread_id=thread_id,
        channel=channel,
    )
    return agent
```

## 五、遇到的问题与解决

| 问题 | 原因 | 解决 |
|---|---|---|
| HITL 确认不触发，工具直接执行 | `details_fn` 用了 `ctx.tool_name`，`BeforeToolCallContext` 无此属性，异常被静默吞掉 | 改为 `ctx.tool_call.name` |
| "generate-mode rejected" / "does not match" 报错 | cubepi 0.13.5 `CheckpointedChannel` 必须绑定 run_id | `build_agent` 加 `run_id` 参数，`prompt(run_id=...)` 传相同值 |
| mypy "Variable ... is not valid as a type" | `SQLiteCheckpointer` 是 PEP 562 惰性导入 | 改为 `from cubepi.checkpointer.sqlite import SQLiteCheckpointer` |
| mypy "object not callable" | `agent.channel` 类型是 `HitlChannel` Protocol 无 `answer` | 测试中 cast 为 `CheckpointedChannel` |
| mypy union-attr | `AgentEvent` 是 pydantic 联合类型，字符串比较无法收窄 | 用 `isinstance()` 收窄 |
| 500 错误无提示 | `build_model()` 抛 RuntimeError 未处理 | 捕获并转 HTTPException 返回可读 detail |
