# 前端模型配置功能开发手册（2026-08-31）

> 开发内容：在科研助手前端增加"模型配置"卡片——用户可直接选择大模型厂商、输入 API Key 即可使用，无需改环境变量。
>
> 开发时间：2026-08-31

---

## 一、开发目标

1. **前端直接配置**：侧栏顶部新增"⚙️ 模型配置"卡片，下拉选择厂商（DeepSeek/Qwen/Kimi/GLM/Anthropic/OpenAI）+ 输入 API Key（+ 可选模型名/Base URL），点击保存即可使用。
2. **后端运行时配置**：新增 `RuntimeConfig` 内存存储 + `GET /config`（回显配置状态，API key 脱敏）+ `POST /config`（保存配置）。
3. **错误可见**：API key 无效等错误通过 SSE `error` 事件推送到前端，红色错误消息展示，而不是静默失败。

## 二、开发过程

### 2.1 需求确认

- 用户："在前端加上配置大模型api的选项，可以让我在前端直接选择一个大模型厂商，然后输入apikey即可使用。"
- 设计决策：
  - 运行时配置存**内存**（MVP 够用，进程重启后需重新配置；后续可落盘/入库）。
  - 支持 6 个厂商：deepseek / qwen / kimi / glm / anthropic / openai，各带默认模型。
  - API key 回显时**脱敏**（前 4 + 后 4，如 `sk-f…3456`），不把明文 key 发回前端。

### 2.2 后端改动（app/config.py）

1. 新增 `RuntimeConfig` dataclass（provider / api_key / model / base_url，`is_configured()` 判断是否可用）。
2. 新增 `PROVIDER_OPTIONS` 列表（6 个厂商的 id / name / default_model）。
3. 新增 `_runtime` 全局变量 + `get_runtime_config()` / `set_runtime_config()`。
4. `build_model()` 优先用运行时配置（`_build_from_runtime()`），未配置时回退环境变量逻辑；错误信息改为提示"请在前端选择大模型厂商并输入 API Key"。
5. `_build_from_runtime()`：preset 厂商走 `create_provider(provider_id, api_key=..., base_url=...)`；anthropic / openai 走各自 Provider 类。

### 2.3 后端改动（app/server.py）

1. 新增 `ConfigBody` pydantic 模型（provider / api_key 必填 min_length=1，model / base_url 可选）。
2. 新增 `GET /config`：返回 `PROVIDER_OPTIONS` + 当前配置状态（含 `api_key_masked` 脱敏）。
3. 新增 `POST /config`：校验 provider 在合法列表中，调 `set_runtime_config()` 保存。
4. `_event_to_sse_dict` 新增 `MessageEndEvent` 分支：`stop_reason == "error"` 时返回 `{"event": "error", "data": {"message": error_message}}`。
5. `post_message` 的 SSE 生成器：收到 `done` 事件后 **break 关闭流**（否则浏览器 fetch 永不结束，一直挂起）。

### 2.4 前端改动（app/static/index.html）

1. 侧栏顶部新增"⚙️ 模型配置"卡片：`#cfg-provider` 下拉、`#cfg-api-key` 密码输入、`#cfg-model` / `#cfg-base-url` 可选、`#cfg-save` 按钮、`#cfg-status` 状态区。
2. 新增 `loadConfig()`：GET /config 填充下拉 + 回显已配置状态（脱敏 key）。
3. `#cfg-save` 点击：校验非空 → POST /config → 成功清空 key 输入 + 状态"✅ 已保存"。
4. `handleSSEFrame` 新增 `error` 事件处理：`addMsg("assistant", "❌ ...", "error")` 红色展示。
5. **SSE 帧解析修复**：sse-starlette 发送 `\r\n\r\n` 帧分隔，原 `split("\n\n")` 解析失败 → 改为 `split(/\r?\n\r?\n/)`，行解析同步改 `split(/\r?\n/)`。

@dataclass
class RuntimeConfig:
    provider: str | None = None
    api_key: str | None = None
    model: str | None = None
    base_url: str | None = None

    def is_configured(self) -> bool:
        return bool(self.provider and self.api_key)

_runtime: RuntimeConfig = RuntimeConfig()

def get_runtime_config() -> RuntimeConfig:
    return _runtime

def set_runtime_config(cfg: RuntimeConfig) -> None:
    _runtime = cfg  # 内存存储，进程重启后需重新配置

    runtime = get_runtime_config()

## 四、验证方式

1. **curl 验证配置接口**：
   - `POST /config` 保存成功 → `{"status":"ok","provider":"qwen"}`
   - 无效 provider → 400 `{"detail":"未知 provider：unknown"}`
   - 空 api_key → 422
   - `GET /config` → 6 个厂商 + 脱敏 key `sk-f…3456`
2. **curl 验证 SSE 错误事件**：假 key 发消息 → `event: error` + `data: {"message": "[qwen/qwen-max @ ...] ProviderAuthFailed: Error code: 401 - ...invalid_api_key..."}` + `event: done`。
3. **浏览器验证**：配置卡片保存 → 发送消息 → 红色错误消息 `❌ [qwen/qwen-max @ ...] ProviderAuthFailed...` 正常展示。
4. **静态检查**：`uv run mypy app/`（0 错误）、`uv run ruff check app/`（全过）、`uv run ruff format --check app/`（全过）、`uv run pytest app/tests/ -q`（14 passed）。

## 五、问题与解决

| 问题 | 原因 | 解决 |
| --- | --- | --- |
| 前端发送消息后一直"助手思考中"，无任何输出 | SSE 流未关闭：`event_generator` 收到 `done` 后没 break，浏览器 fetch 永不结束 | 收到 `done` 事件后 `break` 关闭流 |
| 前端收不到 error 事件（curl 正常） | sse-starlette 用 `\r\n\r\n` 分隔帧，前端 `split("\n\n")` 解析失败 | 改为 `split(/\r?\n\r?\n/)` + 行解析 `split(/\r?\n/)` |
| API key 无效时静默失败 | `MessageEndEvent` 未在 `_event_to_sse_dict` 处理 | 新增分支：`stop_reason == "error"` → SSE `error` 事件 |
